## 1. Risky code patterns at the local-execution surface

### 1.1 What the dev server actually binds (settles a recorded claim)

**Answer: every interface.** `package.json` `dev` is plain `next dev` and `start` is plain
`next start`; neither passes `-H`. No tracked `.env*` exists (all `.env*` are gitignored,
see §2), `next.config.ts` sets no host, and the only scripted invocation that adds flags
is Playwright's `webServer` (`npm run dev -- -p ${PORT}`, `playwright.config.ts:50`), which
adds a port and no host. With no `-H`, `next/dist/server/lib/start-server.js:266` calls
`server.listen(port, undefined)`, which Node binds to the unspecified address (`::`,
dual-stack on Windows, so it also accepts IPv4 on every interface). Next 16.3.3's own CLI
help states the default as `0.0.0.0`.

Correction for the App Master to route (those two docs were **not** edited here):

- `docs/ue58-mcp-convergence-plan.md:15` — **correct in substance**: the server listens on
  every interface. Its other claim, that `/api/blender-mcp/execute` "carries no request
  gate", is **stale**: `execute` and `connect`/`disconnect` have sat behind
  `requireOperator` since 2026-10-13 (fleet-memory), and this run guards `generate`,
  `generate/import`, `assets/download` and `filesystem/watch` too. What is still true: in
  the default no-token mode that gate stops only cross-site *browsers*; any other host on
  the network can call these routes (finding C-1).
- `docs/visual-generation-roadmap.md:20` — **misattributed**: its `0.0.0.0` is ComfyUI's
  `python main.py --listen 0.0.0.0 --port 8188`, not the PoF dev server. It says nothing
  about how `next dev` binds.

### 1.3 Checked and clean

- **No command-line or Python interpolation in these routes.** `blender-mcp/*` sends every
  argument as a JSON field over the addon socket (`service.ts:394` `JSON.stringify(command)`),
  never spliced into Python source; `execute` is arbitrary code *by design* and is
  covered by C-1. No route under these two trees reaches `src/lib/bridge/run-python.ts`
  (its only route caller is `pipeline-artifacts/drain-python`); that client also posts
  `{module, function, args}` as JSON, with a default timeout (`run-python.ts:133`), not an
  interpolated snippet.
- `blender-mcp` `connect` accepts only loopback hosts and a valid port (`route.ts:14-22`).
- The Blender TCP client bounds both time (fast/slow timeouts) and the receive buffer
  (`MAX_RESPONSE_BYTES` = 8 MB, `service.ts:31,335`).
- No route here spawns a process.
